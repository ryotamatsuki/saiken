# Client-Ready Consulting Report Quality Framework

## 1. 目的

本フレームワークは、政策・財政・公金管理分野の調査レポートについて、単なる「情報量」「文章量」「見栄え」ではなく、意思決定に使える品質を評価するためのものである。

愛媛県の基金・債券運用レポートに適用する際は、民間企業向けコンサルレポートと異なり、次を優先制約とする。

1. 安全性
2. 流動性
3. 法令・規程との整合
4. 説明責任・監査可能性
5. その制約下での効率性・収益性

したがって、単純な収益最大化や他県追随はclient-readyな提言とは扱わない。

---

## 2. 100点評価フレーム

| 評価軸 | 配点 | 評価対象 |
|---|---:|---|
| 1. Decision usefulness | 15 | 読後に何を判断し、何を決めるべきか明確か |
| 2. Problem framing | 10 | 問い、対象、時点、制約条件、非対象が明確か |
| 3. Storyline | 10 | 各章が結論に向かって論理的につながるか |
| 4. Evidence quality | 15 | データ、出典、母集団、時点、比較可能性が十分か |
| 5. Analytical depth | 15 | 事実列挙を超え、原因、反証、感応度、代替仮説まで扱うか |
| 6. Benchmarking | 10 | 比較対象の選び方、定義、類似性、差の解釈が妥当か |
| 7. Recommendation quality | 10 | 分析から具体的で条件付きの提言が導かれているか |
| 8. Implementation readiness | 5 | 誰が、いつ、何を、どの順に実行するかが分かるか |
| 9. Risk / limitations | 5 | 不確実性、データ制約、失敗条件、見直し条件を明示するか |
| 10. Communication quality | 5 | Executive Summary、図表、見出し、文章が意思決定を助けるか |
| **Total** | **100** |  |

---

## 3. 評価軸ごとの判定基準

### 3.1 Decision usefulness — 15点

**高評価の状態**

- 最初の数ページで主要なmanagement questionと答えが分かる。
- 「何が分かったか」だけでなく「何を判断すべきか」が明記される。
- 提言に条件、優先順位、トリガーがある。
- 読者が会議・決裁・方針策定にそのまま使える。

**減点要因**

- 調査結果は多いが結局どう判断すべきか不明。
- 結論が「検討が必要」で終わる。
- 数字が出ているが政策判断との接続がない。

### 3.2 Problem framing — 10点

**高評価の状態**

- 1文で中心的な問いを言える。
- 時点、対象資金、対象商品、情報制約、非対象を明示する。
- 「比率を決める問題」なのか「流動性を確保した残余資金を求める問題」なのかが区別される。

**減点要因**

- 問いが途中で変わる。
- R6とR7、期末と年間平均、基金と歳計現金が混在する。

### 3.3 Storyline — 10点

**高評価の状態**

章構成が概ね次の因果を持つ。

`Why now → What peers do → What Ehime needs → What is investable → How to invest → What value/risk arises → How to implement`

各章末に次章へつながるbridgeがある。

**減点要因**

- 各章が単独メモの集合に見える。
- 章の順番を入れ替えても結論が変わらない。

### 3.4 Evidence quality — 15点

**高評価の状態**

- 一次資料を優先。
- 時点・定義・単位・母集団を明示。
- 同じ指標名でも定義が違う場合に比較不能と明記。
- 計算式と入力値の出所を追跡可能。
- 重要数字に再現可能性がある。

**減点要因**

- 報道値を一次統計と同列に扱う。
- 期末値と平均値を同一表で無注記比較。
- 公表されていない愛媛県実運用を推定して事実扱いする。

### 3.5 Analytical depth — 15点

**高評価の状態**

各重要論点について最低でも以下を満たす。

`Fact → Interpretation → Counterargument / alternative explanation → Ehime implication`

加えて重要モデルでは、

- sensitivity
- stress case
- boundary condition
- trigger for revision

を持つ。

**減点要因**

- 他県の比率を並べて終了。
- モデル数値の根拠が「保守・標準・積極」というラベルだけ。
- なぜ別案を採らないかが不明。

### 3.6 Benchmarking — 10点

**高評価の状態**

- benchmarkを「公式類似団体」「運用実務類似団体」「先進事例」に分ける。
- peer selectionの理由を説明する。
- 差を優劣と即断せず、資金用途、財政構造、制度、cash needの違いを検討する。

**減点要因**

- 全国平均だけで判断。
- 高い債券比率をそのままbest practiceとみなす。

### 3.7 Recommendation quality — 10点

**高評価の状態**

提言は次を満たす。

- analysis-derived
- conditional
- prioritized
- measurable
- reversible where uncertainty is high

例：

「435億円を運用する」ではなく、

「最大繰替を1年以内流動性資産でカバーし、基金別1～5年cash-flowを確認後、その残余の範囲内で上限435億円を中心ケースとして段階導入する」

のように記述する。

### 3.8 Implementation readiness — 5点

**高評価の状態**

最低限、次が定義される。

- owner
- decision body
- data required
- update frequency
- limits
- escalation trigger
- implementation phases

### 3.9 Risk / limitations — 5点

**高評価の状態**

- 金利、時価、流動性、信用、再投資、operational、governance riskを扱う。
- 「満期保有なら含み損は無関係」といった過度な単純化を避ける。
- 何が分からないため結論が暫定かを明示する。
- 結論を変更すべき条件を明示する。

### 3.10 Communication quality — 5点

**高評価の状態**

- Executive Summaryだけで主要結論が理解できる。
- 見出しが単なるテーマ名ではなくmessage titleになっている。
- 図表ごとにheadline conclusionがある。
- 文章は短文化ではなく、重要論点に十分な説明量を割く。
- appendixへ追いやる情報と本文に残す情報の線引きが明確。

## 4. Paragraph-level quality rule

重要な分析段落は、原則として次の5要素のどこまで到達しているかを確認する。

1. **Claim** — 何を主張するのか。
2. **Evidence** — その主張を支える数字・事実は何か。
3. **Interpretation** — なぜその結果になっていると考えるか。
4. **Ehime implication** — 愛媛県では何を意味するか。
5. **Decision / Action** — 何を判断・実行すべきか。

全段落に5要素を詰め込む必要はないが、主要論点がEvidenceで止まっている場合は未完成とみなす。

### 例

**弱い記述**

> 埼玉県の債券比率は65.0%である。

**改善された記述**

> 埼玉県のR7基金年間平均残高では債券比率が65.0%である。ただし、愛媛県が同水準を目指す根拠にはならない。比較上重要なのは、埼玉県がどの程度の現預金を残し、どの期間の支出を債券満期でカバーしているかである。愛媛県では基金繰替が大きいため、比率ベンチマークよりcash-flow benchmarkを優先すべきである。

---

## 5. Exhibit quality rule

図表は次の条件を満たす場合に本文へ置く。

1. 図だけで一つの主張が伝わる。
2. titleがテーマ名ではなく結論を述べる。
3. sourceとdefinitionが確認できる。
4. 本文が図の意味を解釈する。
5. 図を削除すると論証が弱くなる。

単なる数値の装飾、本文と重複するだけのグラフ、比較定義が揃っていないランキング図は避ける。

## 6. Client-ready gate

総合点だけではなく、critical criteriaを設定する。

### Gate A — Evidence integrity

以下のいずれかがあればFAIL。

- 出典不明の主要数字
- 年度・時点の誤混同
- 公表されていない実運用の事実認定
- 再現不能な主要計算
- 比較定義の重大な不一致を無注記で使用

### Gate B — Decision logic

以下が揃わなければclient-readyとしない。

- 中心提言
- 提言の根拠
- 代替案又は反対シナリオ
- 提言を変更すべき条件

### Gate C — Implementation

少なくとも以下を示す。

- next 90 days
- next fiscal year
- governance owner
- monitoring KPIs / limits

### Gate D — Communication

- Executive Summaryを5分で読んで主要判断が分かる。
- 主要図表を追うだけでもストーリーが理解できる。
- 各主要章にEhime implicationがある。

## 7. スコア帯

| Score | Status | 意味 |
|---:|---|---|
| 90–100 | CLIENT-READY PASS | 重要な追加修正なしで提出可能 |
| 85–89 | CONDITIONAL CLIENT-READY | 軽微な修正後に提出可能 |
| 70–84 | SENIOR MANAGER REVIEW REQUIRED | 骨格は有効だが分析・提言・実装に補強が必要 |
| 50–69 | MAJOR REVISION | 構造又はevidence chainの再構築が必要 |
| <50 | REDESIGN | 問い・構成・データ設計から再設計 |

ただしGate AがFAILの場合は点数にかかわらずclient-readyとはしない。

---

## 8. 愛媛県レポートへの適用原則

現行稿の改稿では、文章量の目標値を先に置かない。各章について、以下の順で必要な厚みを判断する。

1. この章で答える問いは何か。
2. 結論は何か。
3. 結論を支えるevidenceは十分か。
4. counterargumentはあるか。
5. 愛媛県への含意は何か。
6. 次の意思決定にどうつながるか。

この6点が満たされた結果として文章量が1.5～2倍になることは許容するが、同じ内容の言い換えによる増量は評価しない。
